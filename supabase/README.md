# 서버 연결 (Supabase) — 설치 순서

이 문서대로 하면 30분 안에 끝납니다. 순서를 지켜 주세요.

지금까지는 데이터가 **브라우저 한 대 안에만** 있었습니다. 다른 PC에서 열면 아무것도
없고, 20시간이 지나면 초기화됐습니다. 이 작업이 끝나면 데이터가 서버에 남고,
대표님·컨설턴트·고객이 각자의 기기에서 **같은 데이터**를 보게 됩니다.

---

## 0. 시작 전 확인 두 가지

**리전(Region)** — Supabase 프로젝트가 어느 나라에 있는지 확인하세요.
Dashboard → Project Settings → General → Region.
실제 기업고객의 사업자번호·대표자 생년월일·연락처가 올라가므로 **Northeast Asia (Seoul)**
을 권합니다. 다른 리전이면 개인정보가 국외로 나가고, 고객에게 국외이전 고지가 필요해집니다.
리전은 나중에 바꿀 수 없습니다 — 다르면 지금 프로젝트를 새로 만드는 편이 낫습니다.

**요금제** — 무료 플랜은 **1주일 동안 접속이 없으면 프로젝트가 일시정지**됩니다.
실제 고객 데이터를 넣기 시작하면 Pro(월 $25)로 올리세요. 매일 쓰신다면 당장은
무료로 시작해도 되지만, 고객 Portal을 열어주는 시점에는 반드시 올려야 합니다.

## 1. SQL 한 번 실행

**(1) 먼저 로그인 계정부터**
Dashboard → **Authentication** → Users → **Add user** → *Create new user*
- Email: 대표님이 쓰실 이메일
- Password: 쓰실 비밀번호 (6자 이상)
- **Auto Confirm User: 켜기** ← 이걸 켜야 확인 메일 없이 바로 로그인됩니다

**(2) SQL 실행**
Dashboard → **SQL Editor** → New query →
편집기 안을 클릭하고 **`Ctrl+A`(전체 선택) → `Ctrl+V`(붙여넣기) → Run**.

> **`Ctrl+A` 를 꼭 먼저 누르세요.** 그냥 붙여넣으면 편집기에 있던 글자가 맨 아래에 남아
> `syntax error at or near ...` 오류가 납니다. 그때는 **맨 아랫줄의 남은 글자만 지우고
> 다시 Run** 하면 됩니다. 오류가 나면 아무것도 만들어지지 않으므로 몇 번을 다시 해도 안전합니다.

바로 복사할 수 있는 주소:
```
https://raw.githubusercontent.com/sanghohoho0813-lab/KPJKcorp/claude/read-and-answer-tbrjsf/supabase/setup.sql
```

표 24개, 접근 권한, 파일 보관함 3개가 한 번에 만들어지고, (1)에서 만든 계정이
자동으로 **대표 권한**을 받습니다.

실행이 끝나면 아래 같은 표가 한 줄 나옵니다. 이것으로 확인하세요.

| 표 | 권한정책 | 파일보관함 | 실시간 | 대표계정 | 다음 할 일 |
|---|---|---|---|---|---|
| 24 | 56 | 3 | 12 | 대표님이메일 | 설치 완료. Project Settings → API … |

- **권한정책 56**: 2026-10-01 고객 데이터 보호 강화로 57 → 56 (고객이 매출기회 표를 직접 읽던 정책을 없애고 고객용 보기로 대체).
- **실시간 12**: 고객이 폰에서 올리면 대표 PC 화면에 1~2초 안에 뜨게 하는 설정입니다. 0 이어도 앱은 15초마다 다시 읽으므로 동작은 같습니다(조금 늦을 뿐).

- **대표계정이 "아직 없음"** 이면 (1)을 먼저 하지 않으신 것입니다. 계정을 만들고 이 파일을 한 번 더 실행하세요.
- **로그인 계정이 여러 개**여서 대표를 못 고른 경우에는 "다음 할 일" 칸에 적힌 한 줄을 이메일만 바꿔 실행하면 됩니다.
- 중간에 노란 **NOTICE** 가 여러 줄 나오는 것은 정상입니다. 오류가 아닙니다.
- **여러 번 실행해도 안전합니다.** 이미 있는 것은 건너뛰고 데이터를 지우지 않습니다.
- `syntax error` 가 났다면 **아무것도 만들어지지 않은 상태**입니다. Postgres 는 전체를 하나로 묶어
  거부하므로 중간까지 만들어지는 일이 없습니다. 지금 상태가 궁금하면 이것만 따로 실행해 보세요:

  ```sql
  select
    (select count(*) from information_schema.tables
      where table_schema = 'public' and table_type = 'BASE TABLE') as "만들어진 표",
    (select count(*) from auth.users)                              as "로그인 계정";
  ```

> 이 파일에는 표 · 접근 권한 · 파일 보관함 · 대표 계정 연결이 모두 들어 있습니다.
> 예전처럼 여러 파일을 순서대로 실행하실 필요가 없습니다.

## 2. 앱에 연결 정보 넣기

Dashboard → **Project Settings** → **API** 에서 두 값을 복사합니다.

| Supabase 화면의 이름 | 넣을 곳 |
|---|---|
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` |
| Project API keys → **anon public** | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |

프로젝트 루트에 `.env.local` 파일을 만들고:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

> **service_role key 는 절대 넣지 마세요.** 그 열쇠는 모든 권한 검사를 통과합니다.
> `anon public` 은 브라우저에 그대로 나가도 되는 값입니다 — 그 열쇠로 할 수 있는 일은
> setup.sql 2부(접근 권한)가 전부 정하기 때문입니다.

`npm run dev` 로 다시 띄우면 로그인 화면에 **서버 연결** 표시가 붙습니다.
배포(Vercel 등)한다면 같은 두 값을 그쪽 환경변수에도 넣으세요.

### 연결 확인 — 버튼 한 번

대표 계정으로 로그인한 뒤 **설정 → 데이터 → 서버 → 연결 점검** 을 누르세요. 아래 일곱 가지를 순서대로 보고,
막힌 곳마다 무엇을 하면 되는지 한 줄로 알려 줍니다. 읽기만 하고 아무것도 바꾸지 않습니다.

| 점검 | 막혔을 때 흔한 원인 |
|---|---|
| 연결 정보 | `.env.local` 오타 · **service_role 키를 넣음**(즉시 교체 안내) |
| 서버 응답 | 프로젝트 일시정지(무료 플랜 1주 미접속) · URL 과 키가 다른 프로젝트 것 |
| 서버 로그인 | 데모 계정으로 로그인한 상태 |
| 표 24개 | setup.sql 미실행 또는 옛 버전 |
| 최신 설정 항목 | 옛 setup.sql 로 설치됨 → 최신본 다시 실행 |
| 권한 함수 · 내 역할 | 대표 계정 연결 누락(1단계의 "다음 할 일" 한 줄) |
| 파일 보관함 3개 | setup.sql 미실행 (18차에 기업 서류함용 vault 가 추가됨 — 예전 것을 돌렸다면 한 번 더 실행) |

모두 초록이면 끝입니다. 막힌 곳이 있으면 **결과 복사** 를 눌러 담당자에게 그대로 보내시면 됩니다(키 값은 들어가지 않습니다).

이 두 줄이 비어 있으면 앱은 **지금까지처럼 브라우저 저장소(데모 모드)** 로 돕니다.
발표·시연용으로는 그대로 쓰시면 됩니다.

## 3. 나머지 계정 만들기

앱에 대표 계정으로 로그인한 뒤 **설정 → 사용자 관리**에서 컨설턴트와 고객 담당자
계정을 만듭니다. 비밀번호는 그 자리에서 정해 전달하고, 본인이 로그인 화면의
"비밀번호를 잊으셨나요?"로 바꾸게 하시면 됩니다.

고객 계정은 **기업고객을 먼저 등록한 뒤**에 만들어야 소속이 연결됩니다.
기업 상세 화면에 "담당자 Portal 계정 없음" 안내가 뜨면 거기서 바로 만들 수 있습니다.

기업을 등록할 때 **담당 컨설턴트를 꼭 지정하세요.** 기본값은 등록한 사람(대표)입니다.
컨설턴트는 자기 담당 기업의 문의만 받고, 고객 제출의 검토 업무도 담당 컨설턴트에게 갑니다.

**대표 이름** — setup.sql 이 자동으로 대표 권한을 줄 때 이름은 이메일 앞부분으로 들어갑니다.
설정 → 사용자 관리에서 실제 이름으로 바꿔 주세요. 실증 기록에 그 이름이 찍힙니다.

### 확인 메일을 쓸지 정하기
Authentication → Providers → Email → **Confirm email**
- **켜두면**(기본): 계정을 만들면 본인에게 확인 메일이 가고, 확인해야 로그인됩니다. 더 안전합니다.
- **끄면**: 만들자마자 바로 로그인됩니다. 비밀번호를 직접 전달하는 방식이면 이쪽이 편합니다.

## 4. 컨설턴트 열람 범위

지금은 **전체 공유** 입니다 — 컨설턴트가 모든 기업고객을 봅니다.
나중에 "자기 담당만" 으로 바꾸려면 설정 화면에서 전환하면 되고, 데이터베이스 정책이
즉시 따라 바뀝니다. 코드를 고칠 필요가 없습니다.

SQL로 직접 바꾸려면:
```sql
update public.app_settings set consultant_scope = 'own' where id = 1;   -- 내 담당만
update public.app_settings set consultant_scope = 'all' where id = 1;   -- 전체 (기본)
```

## 5. 권한이 정말 막히는지 확인하기

정책을 "설정했다"와 "실제로 막는다"는 다릅니다. 노트북에 Postgres가 있다면
`test/000_supabase_stub.sql` → `setup.sql` → `test/010_rls_test.sql` 순서로
실행해 79개 항목을 직접 확인할 수 있습니다. 이 저장소에서는 전부 통과했습니다(2026-09-30).
실제 Supabase(로컬 Docker)에 대표·컨설턴트·고객 계정으로 붙인 화면 검증은 `tools/pilot/` 에 있습니다.

- 고객은 자기 회사만 보이고, 남의 회사는 기업·프로젝트·문의·파일 어느 것도 안 보임
- 고객은 상담기록·업무를 아예 볼 수 없음 (내부 전용)
- 고객은 초안 견적과 미발송 자료요청을 볼 수 없음
- 고객은 견적을 "계약전환"으로, 자료요청을 "검토완료"로 바꿀 수 없음 (제출·수락까지만)
- 컨설턴트도 고객도 스스로 대표 권한을 가질 수 없음
- 활동 기록은 누구도 수정·삭제할 수 없음
- 사용 중지된 계정은 아무것도 못 봄, 비로그인은 접근 자체가 안 됨
- 고객은 내부 업무·자동 기록·고객용 알림을 직접 만들 수 없음 — 대신 제출·문의·상담요청·견적 회신을 하면
  **서버가 후속(검토 업무·접수 알림·단계 변경·자동 기록)을 만듦** (setup.sql 2부 14항 트리거)

## 서버 모드에서 달라지는 것

- **자동 갱신** — 로그인한 동안 15초마다, 그리고 창을 다시 볼 때 서버의 최신 내용을 읽습니다.
  고객이 휴대폰에서 올린 자료가 담당자 PC에 새로고침 없이 나타납니다. 새로고침하면 브라우저에 남은 옛 화면이 아니라 서버에서 새로 읽습니다.
- **저장 방식** — 새 행은 추가, 기존 행은 바뀐 칸만 보냅니다. 두 사람이 같은 기업의 다른 칸을 고쳐도 서로 덮지 않습니다.
- **연결이 끊기면** — 화면 위에 노란 줄로 알리고, 연결이 돌아오면 저절로 사라집니다.
  로그인 화면에서 서버에 닿지 않으면 "비밀번호 틀림"이 아니라 연결 문제로 안내하고,
  **이 브라우저만 데모 모드로 전환**하는 버튼을 보여줍니다(서버 데이터는 그대로). 주소 끝 `/login?demo=1` 로도 띄울 수 있습니다.

## 알아두실 것

**동시 수정** — 두 사람이 같은 기업 정보를 동시에 고치면 나중에 저장한 쪽이 남습니다.
컨설턴트 5명 규모에서는 거의 생기지 않고, 모든 변경은 활동 기록에 남아 추적됩니다.
사람이 늘면 그때 항목별 잠금을 붙이면 됩니다.

**저장 실패** — 화면이 먼저 바뀌고 서버 저장이 뒤따릅니다. 실패하면 붉은 알림과 화면 위 노란 줄이 뜹니다.
그냥 넘어가면 그 변경은 다음 자동 갱신 때 서버 내용으로 되돌아갑니다 — 다시 입력해 주세요.

**백업** — 설정 → 백업 내보내기는 서버 연결 후에도 그대로 씁니다.
Supabase 자체 백업(Pro 플랜)과 별개로, 월 1회는 내려받아 두시길 권합니다.
