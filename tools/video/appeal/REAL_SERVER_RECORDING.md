# ① 구간(약 01:02 – 01:34) 운영 서버 연속 녹화 — 계정 · 촬영 절차

지금 영상의 ① 구간은 **실제 프로그램 화면 녹화(데모 환경)** + **서버 트리거 실제 실행 결과(로컬 시험 DB)** 입니다.
"고객 휴대폰 ↔ 담당자 PC 가 같은 서버로 이어져 한 번에 움직이는 연속 녹화"는 이 작업 환경에서 만들 수 없었습니다.

| 막힌 곳 | 이유 |
|---|---|
| 데모 환경 | 데이터가 브라우저 안에만 저장된다 — 휴대폰 창과 PC 창이 서로의 변화를 받지 못한다 |
| 로컬 서버(Supabase 전체) | 로그인 · 파일 · 실시간 서버 이미지를 받는 단계가 데이터 한도로 막힘. 외부 서버 프로그램을 내려받아 실행하는 것은 권한상 하지 않음 |
| 운영 서버 | 촬영용 테스트 계정이 없다 — 대표님 계정으로 찍으면 실제 고객사 이름이 화면에 나온다 |

가짜 화면이나 애니메이션으로 대신 만들지 않았습니다. 아래 준비만 해 주시면 실제 운영 서버에서 연속 녹화할 수 있습니다.

## 2. 녹화 방법 — 둘 중 하나

**A. 제가 녹화 (권장 — 두 화면이 정확히 같은 시각)**
두 테스트 계정의 아이디 · 임시 비밀번호를 알려 주시면, 운영 서버에 붙은 앱을 휴대폰 크기(390×844) 창과 PC(1440×900) 창으로
동시에 띄워 아래 순서를 **한 번에 끊지 않고** 녹화합니다. 두 창은 서로 다른 로그인이라 데이터는 서버를 거쳐서만 오갑니다.
끝나면 두 계정을 사용 중지하시면 됩니다. (화면에는 "휴대폰 크기 브라우저"라고 적습니다)

**B. 대표님이 직접 (실제 휴대폰)**
휴대폰 화면 기록(아이폰: 제어센터 ● / 갤럭시: 빠른 설정 → 화면 녹화)과 PC 화면 녹화(Windows `Win + Alt + R`, 또는 OBS)를
**같이 켜고** 아래 순서를 진행해 두 파일을 주세요. 두 화면은 "고객 제출 → 서버가 같은 순간에 보내는 PC 업무 · 고객 알림"
시점으로 맞춥니다(실시간 전송 지연 1초 안팎).

표기는 "실제 화면 녹화 · 운영 서버 · 가상 기업"으로 고칩니다. 다른 장면 · 자막 · 음성 · 길이는 그대로입니다.
