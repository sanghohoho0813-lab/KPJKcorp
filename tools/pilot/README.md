# 실서버 파일럿 검증 (FINAL LIVE PILOT)

실제 서버(Supabase)에 붙은 앱을 **대표 1 · 컨설턴트 1 · 고객 2** 실제 계정으로 조작해,
"실제로 작동한다"를 화면과 서버 DB 양쪽에서 확인합니다. 관리자 미리보기가 아니라 **고객 계정으로 직접 로그인**합니다.

현장 당일 순서는 아래 [현장 점검표](#현장-점검표-내일-아침)를 보세요.

## 로컬 Supabase 로 재현 (Docker)

실제 Supabase 와 같은 인증 · DB · 권한 · 파일 보관함을 이 PC에 띄웁니다. 실제 고객 데이터는 넣지 않습니다.

```bash
tools/pilot/local-supabase.sh start      # 대표 계정 → setup.sql → .env.local (실서버용 .env.local 은 덮지 않음)
npm run build && npm start
node tools/pilot/setup.mjs && node tools/pilot/loop.mjs pc && node tools/pilot/loop.mjs mobile && node tools/pilot/persist.mjs && node tools/pilot/fallback.mjs
tools/pilot/local-supabase.sh reset      # 처음 상태로
```

실제 Supabase 프로젝트로 돌리려면 `PILOT_DB_URL`(Database 연결 문자열)과 계정 비밀번호
`PILOT_CEO_PW · PILOT_CON_PW · PILOT_C1_PW · PILOT_C2_PW` 를 환경변수로 넣습니다. 비밀번호는 코드에 두지 않습니다.

## 현장 점검표 (내일 아침)

### A. 전날 밤 / 출발 전 (15분)

1. Supabase → SQL Editor → **최신 `setup.sql` 전체 실행** → 결과 한 줄이 **표 26 · 권한정책 61 · 파일보관함 3 · 실시간 12** 인지 확인.
   이미 돌린 적이 있어도 다시 돌립니다(이번에 고객 제출의 자동 후속을 서버가 만드는 부분이 추가됐습니다). 데이터는 지워지지 않습니다.
2. `.env.local` 에 **URL 과 anon 키 두 줄만**. service_role 키 금지.
3. 앱 빌드 후 대표 계정 로그인 → **설정 → 데이터 → 서버 → 연결 점검** → "모두 정상입니다".
4. 설정 → 사용자 관리에서 **대표 이름을 실제 이름으로** (자동 생성 시 이메일 앞부분이 이름으로 들어갑니다 — 실증 기록에 그대로 찍힙니다).
5. 계정 4개: 대표 1 · 컨설턴트 1 · 고객 2. **고객 계정은 기업을 먼저 등록한 뒤** 만듭니다.
6. 파일럿 기업은 **비식별 이름**으로. 기업 등록 시 **담당 컨설턴트를 반드시 지정** — 컨설턴트는 자기 담당 기업의 문의만 봅니다.
7. 파일럿 프로젝트를 "자료요청" 단계로, 요청자료 1~2건 등록.

### B-2. 대표 화면 ↔ 고객 화면 연결 시연 (PC = 대표, 휴대폰 = 고객)

대표 PC 는 **기업고객 → 해당 기업** 화면을 띄워 둡니다. 서로의 화면은 **1~2초 안에** 바뀌고, 화면 구석에 **알림 카드**가 뜹니다(누르면 해당 화면으로). 실시간이 꺼져 있어도 15초 안에는 바뀝니다.

| # | 대표 PC (기업 상세) | 고객 휴대폰 |
|---|---|---|
| 1 | **서류함** → 법인등기부등본 칸 **고객에게 요청** → 기한 확인 → 고객에게 요청 | 알림 · **자료제출**에 "법인등기부등본" + "카카오톡으로 보내셔도 되고…" |

### B-3. 내일 한 사이클 (대표 PC + 고객 휴대폰) — `cycle.mjs` 와 같은 순서

1. **기업 등록** — 기업고객 → 등록(사업자등록증 PDF 올리면 자동 채움). 담당 컨설턴트 지정.
2. **고객 계정** — 기업 상세 → 고객 플랫폼 → 계정 만들기 → 뜨는 **안내 문구 복사** → 카카오톡으로 고객에게. (빨간 "이대로는 로그인이 안 됩니다"가 뜨면 Supabase Confirm email 끄기 — 안내 그대로)
3. **진행 업무 + 추가** → 분야(예: 가지급금) 클릭 → 등록.
4. 단계 칸 **1 자료 요청** → "가지급금 서류 모두 담기" + 직접 입력 → 메시지 칩 → 보내기.
5. 고객: 안내 문구의 주소로 로그인 → 노란 줄 **지금 바꾸기** → 비밀번호 변경.
6. 고객: 홈 "지금 해야 할 일" → 서류 누르고 **사진 찍어 올리기**. → 대표 PC 구석에 카드(1~2초).
7. 대표: 요청자료 → 확인 → 보완 요청 또는 검토 완료. 고객 화면 즉시 반영.
8. 단계 칸 **3 진행 중** → "곧 결과를 정리해…" 칩 → 보내기 / 일정 등록 / 고객에게 제안하기.
9. 고객: 홈 "다음으로 검토할 성장과제" → **검토하고 싶어요** 또는 상담 요청 → 대표 PC 카드.
10. 대표: 고객 플랫폼 → **고객 성장과제** → 연락함 → **진행 업무로 시작**.
11. 단계 칸 **4 완료** → 결과 보고서 파일 함께 → 보내기. 고객: 완료자료 내려받기, 홈 "완료한 과제".

### C-0. "다른 기기에서 입력한 게 안 보여요"
1. 두 기기 모두 화면 위 표시 확인: **DEMO DATA**(주황)면 그 브라우저는 데모 모드 — 입력한 내용은 그 브라우저에만 있습니다. 지금은 빨간 줄 "이 브라우저는 데모 모드입니다"가 늘 뜹니다.
2. 로그인 아이디 확인: 서버 계정(대표님 실제 이메일)인지, 데모 계정(ceo@kpjk.co.kr)인지.
3. Supabase → Table Editor → **companies** 에 그 기업이 있는지.
4. 데모 브라우저에 남아 있다면: 그 브라우저에서 **입력한 내용 엑셀로 받기** → 서버 계정으로 로그인 → 기업고객 → **일괄 등록**에 그 파일.
5. 빨간 줄 "서버에 아직 저장되지 않은 변경 N건"이 보이면 인터넷 연결 후 **다시 보내기**. 창을 닫아도 그 브라우저에 보관돼 다음 로그인 때 다시 보냅니다.

### C. 비상시

| 상황 | 대처 |
|---|---|
| 로그인 화면에 "서버에 연결되지 않습니다" | 인터넷 확인 → 안 되면 **"이 브라우저를 데모 모드로 전환"** → 데모 계정으로 시연 계속 (서버 데이터는 그대로) |
| 서버는 되는데 데모로 바꿔야 할 때 | 주소 끝에 **`/login?demo=1`** |
| 데모에서 서버로 돌아가기 | 로그아웃 → 로그인 화면의 **"서버 연결로 돌아가기"** |
| 사용 중 화면 위에 노란 줄 "서버에 연결하지 못했습니다" | 인터넷이 돌아오면 저절로 사라집니다. **다시 연결** 버튼으로 바로 시도 |
| 비밀번호를 맞게 넣었는데 "서버에 연결하지 못했습니다" | 비밀번호 문제가 아닙니다 — 인터넷·Supabase 일시정지(무료 플랜 1주 미접속) 확인 |

### 하지 않는 것

- 개선율 · ROI · 절감시간 같은 **검증되지 않은 성과 수치는 말하지도 띄우지도 않습니다.** 화면에도 없습니다.
- 실제 고객의 개인정보·민감자료는 파일럿에 올리지 않습니다(계약 제17조③). 비식별 기업 · 시험 파일로 합니다.
