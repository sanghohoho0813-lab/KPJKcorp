# LossGuard 시연 화면 (독립 실행 · 가상 자료)

기존 KPJK AX 와 분리된 **독립 시연 환경**이다. 운영 DB · 로그인 · 고객 데이터와 연결되지 않는다.

## 실행

```bash
# 저장소 루트에서(처음 한 번: npm install — React 를 저장소의 node_modules 에서 쓴다)
node lossguard/demo/serve.mjs          # → http://127.0.0.1:4310 을 브라우저로 연다
PORT=4400 node lossguard/demo/serve.mjs # 포트 바꾸기
```

- 처음 실행할 때 화면 묶기 도구(esbuild 0.25.10)를 `npx` 로 한 번 내려받는다. 저장소의 `package.json` 은 바꾸지 않는다.
- 화면 파일은 운영체제 임시 폴더에 만들어지고 저장소에는 남지 않는다.
- 끝내려면 터미널에서 `Ctrl+C`. 브라우저에 저장된 시연 자료는 첫 화면의 "시연 자료 모두 지우기"로 지운다.

## 해 보는 순서(약 5분)

1. 오른쪽 위 **확인자**에 이름을 적는다(판단 · 상태 변경마다 남는다).
2. **예시 현장 A 로 시작** — 가상 계약 내역서(.xlsx) · 변경 내역서 1차(.xlsx) · 정산서(.xls) · 매입 장부(CSV) 4개가 올라간다.
3. **분석하기** → ④ 확인할 결과: 계산 불일치 · 미확인 불일치(중복 가능성 포함) · 자료 부족으로 나뉘어 보인다. 결과를 누르면 원본 시트의 칸이 강조되고 계산 과정이 나온다.
4. 처리 기록: 확인 시작 → 실제 문제로 확인 → 조치 기록 → 완료(실제 반영 금액 또는 "반영 금액 없음").
5. ③ 항목 연결: "확인 필요" 짝을 같은 항목 · 다른 항목으로 판단한다. "우리 회사 다른 현장에도 적용"을 고르면 회사 규칙으로도 남는다.
6. ② 문서 읽기 확인: 열 역할을 고칠 수 있다. 고친 뒤 **다시 분석** → 바뀐 것이 비교되어 나온다.
7. ⑥ 기록: 분석 회차 · 사람 판단(판 · 출처 · 확인자). ⑦ 보고서 → **인쇄 · PDF로 저장**.
8. 첫 화면에서 **예시 현장 B 추가** → 분석 → 항목 연결의 "회사 규칙" 칸: 현장 A 의 판단이 다시 쓰인다.

## 자료가 밖으로 나가지 않는 구조

| 장치 | 내용 | 확인 방법 |
|---|---|---|
| 브라우저 안 분석 | 파일 읽기 · 분석 · 보고서를 모두 브라우저 안에서 한다 | 종단 시험이 모든 요청을 기록 — 화면 파일 GET 뿐 |
| 서버 | 127.0.0.1 에서만 열림, 화면 파일 3개만 GET 으로 내줌, 그 밖은 404 · 405 | `serve.mjs` |
| 보안 정책(CSP) | `connect-src 'none'` 등 — 화면 코드가 외부로 보내려 해도 브라우저가 막음 | 종단 시험이 `fetch` 를 시도해 막히는 것을 확인 |
| 코드 검사 | 엔진 · 제품 로직 · 화면 코드에 네트워크 호출 · 외부 주소 · AI API 가 없음 | `test/boundary.test.ts` |
| 저장 | 원본 파일은 저장하지 않고, 개인정보를 지운 "읽은 값"만 이 브라우저(IndexedDB)에 | `app/ingest.ts` |

## 시험

```bash
node lossguard/demo/e2e.mjs --shots /tmp/shots --pdf /tmp/report.pdf   # 실제 브라우저로 처음부터 끝까지(Playwright · Chromium 필요)
```

## 한계(시연판)

- 가상(합성) 자료로만 시험했다. 실제 현장 자료의 정확도는 측정 전이다.
- 분석은 화면과 같은 흐름에서 돈다(큰 파일이면 잠시 멈춘 듯 보일 수 있음 — 작업 분리는 다음 단계).
- 매입 장부의 열 지정 고치기, 여러 사람 동시 작업, 로그인 · 권한, 서버 저장은 없다(포털 연결 설계는 `LOSSGUARD_SPEC.md` §M).
- 회사 규칙의 가명 · 개인정보: 같은 사람 이름의 가명은 파일 하나 안에서만 같다(가명 대응표를 저장하지 않기 때문).
